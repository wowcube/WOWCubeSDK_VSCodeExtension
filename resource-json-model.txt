WOWCube Resource Studio JSON Model

File: wowcubeapp-resources.json
Schema version: 2

The file stores one resource bundle. It contains resource records, source folder
paths, and shared classification definitions. Image files remain separate; the
JSON references them by path. The implemented resource types are palette,
sprite, map, font, and sound. Exported device data is not part of this model.

Bundle fields

schemaVersion: number
    Always 2 for this model.
sourceFolders: string[]
    Folders used to discover source assets. Paths are relative to the folder
    containing the JSON file. "." means that folder. Use forward slashes.
    A sprite source can be outside these listed folders, while still relative
    to the folder containing the JSON file.
resources: Resource[]
    Palette, sprite, and future resource records in one array.
registries: object
    groups: string[] — ordered group names.
    types: string[] — ordered object classification names.
    tags: string[] — ordered tag names.

Common resource fields

id: string
    Stable resource identity. References use this value, not the resource name.
    Treat IDs as opaque strings; the editor currently generates 32 hex digits.
name: string
    Resource name, independent of its source file name and ID.
    "icon" is allowed for sprites; it remains reserved for other resource types.
type: string
    Resource kind: "palette", "sprite", "map", "font", or "sound" for the implemented types.

Palette fields

type: "palette"
colors: string[]
    Current palette colors, indexed from zero. Each string is #RRGGBB or
    #RRGGBBAA. Six-digit RGB implies alpha 255; the last two digits of RGBA
    encode alpha, with 00 transparent and ff fully opaque.
mappingColors: string[]
    Generated palette colors used to assign source pixels to palette indices.
    There is one entry for each colors entry, in the same order. These are
    separate from the current colors: colors[15] can change while
    mappingColors[15] retains its generated value. Pixel matching uses
    mappingColors; displayed output uses colors at the resulting index.
    Alpha-form matching includes alpha, so identical RGB values can
    occupy separate entries with different opacity.
colorCount: integer
    Requested palette capacity, not necessarily colors.length. Generation can
    produce fewer entries than requested. The default requested capacity is 256.
transparentIndex: 0
    Always zero. colors[0] and mappingColors[0] are #00000000, reserved for
    transparency. The requested capacity (2–256) includes this reserved entry.

The current palette-builder produces #RRGGBBAA colors quantized to RGB565+A5.
On generation, colors and mappingColors initially contain the same values.
Edited colors use the same RGB565+A5 precision. Quantization discards the low
3 bits of R/B/A and the low 2 bits of G, then expands by bit replication:
5-bit channels: (value << 3) | (value >> 2).
6-bit channels: (value << 2) | (value >> 4).
Here value is the reduced 5-bit or 6-bit channel. For example, #7f7f7f7f
becomes #7b7d7b7b. Six-digit edits retain six digits with implicit alpha 255.
The JSON does not store sprite pixel-index arrays or embedded image data.

Matching source pixels to palette indices

The current indexed preview uses nearest-color matching against mappingColors.
For a source pixel (r, g, b, a) and a mapping entry (R, G, B, A), channels are
8-bit values from 0 to 255. A six-digit entry has A = 255.

For blend "alpha" or "additive", the distance is:
    (r - R)^2 + (g - G)^2 + (b - B)^2 + (a - A)^2
For blend "opaque" or "bg", the distance is:
    (r - R)^2 + (g - G)^2 + (b - B)^2

All included channels have equal weight. There is no gamma correction,
perceptual weighting, or extra source quantization before this comparison.
An exact match has distance zero and wins over any non-exact match.

Entries are scanned in ascending index order. Equal distances keep the first
eligible entry, so the lowest eligible index wins. If mappingColors[56] and
mappingColors[57] are both #181c18, index 56 wins. Duplicates only in colors
do not affect matching, because the comparison uses mappingColors.

For source pixels with alpha greater than zero, compare entries 1 through
the last mapping entry. Index 0 is always excluded. Opaque-form matching
ignores mapping and source alpha. If there are no candidates, use index 0.

A source pixel with alpha zero bypasses nearest-color matching. Its index is
always 0. Such pixels remain transparent.

After matching, RGB comes from colors[index]. Alpha-form output uses that
entry's alpha directly, without multiplying it by source alpha. Opaque-form
output uses alpha 255. Index 0 always has zero alpha.
These rules describe the current preview; no export pixel encoding is stored
in the JSON model.

Sprite fields

type: "sprite"
source: string
    PNG path relative to the folder containing the JSON file, using forward
    slashes. For example: "characters/hero.png".
paletteId: string | null
    ID of the palette resource used by a palettized sprite; null for RGB565.
colorMode: "palette" | "rgb565" | "rgb6666"
    "palette": indexed color using paletteId.
    "rgb565": direct color without a palette.
    "rgb6666": reserved, unsupported placeholder.
blend: "opaque" | "alpha" | "additive" | "bg" | "bump" | "dudv" | "refl"
    In palette mode, Alpha and Additive use alpha-form palettes; Opaque and BG
    use opaque-form palettes. BG currently behaves as Opaque. Bump, DuDv and Refl are reserved,
    unsupported placeholders. RGB565 allows only Opaque without a palette.
fullsize: boolean
    true means 1:1 source-to-runtime pixels; false means doubled runtime size.
    Additive blended sprites cannot use FULLSIZE: they will not be drawn (warning V-032).
    Pivot and collider coordinates remain in source pixels in either case.
dither: boolean
    RGB565 dithering flag. Palettized sprites store false.
compression: "plain" | "softkey" | null
    RGB565 encoding selection. Palettized sprites store null.
softkey: {key: string, threshold: integer} | null
    Color Key settings for "softkey" encoding. key is #RRGGBB; threshold is
    the matching tolerance. This field may be omitted when unused; the editor
    normally writes null. "Color Key" is the UI label; the JSON key remains
    softkey.
number: integer
    Application-defined Number metadata; not the sequence index. Defaults to 0.
frameRate: integer
    Engine hold counter (Rate), not frames per second. Sequence frames use
    0–127; at engine multiplier 1 the duration is (frameRate + 1) * 50 ms.
    Static sprites retain the default 1. Runtime multipliers may change timing.
sequence: {id: string, name: string, index: integer} (optional)
    Present only on sprites belonging to an animation sequence. id identifies
    the sequence, name is shared by all its frames and unique across resources
    and sequences, and index is its zero-based order. Indices are contiguous.
    Every animation requires at least two frames for compilation. Both name
    and name + "_end" are reserved identifiers and must not collide with any
    resource name or another animation's generated identifiers.
    Every frame is a distinct sprite with a globally unique ID and resource
    name, even when a source image occurs more than once. Number is unrelated.
    There is no animation resource type. A frame belongs to one sequence.
    The fixed sequence origin is (0, 0), in source pixels with Y down. A frame
    displayed with top-left (X, Y) stores pivot {x:-X, y:-Y}. Different source
    dimensions do not change the origin. FULLSIZE scaling is applied later by
    the existing runtime/export conversion, not by changing these pivots.
    Preview looping is not exported. The resource builder links consecutive
    frame IDs through Seq, including the last back to the first. It generates
    BMP_<name> and BMP_<name>_end for the first and last frames respectively.
group: string | null
    Assigned name from registries.groups, or null.
objectType: string | null
    Assigned name from registries.types, or null. This is classification;
    the common type field still identifies the resource kind.
tags: string[]
    Assigned names from registries.tags. An empty array means no tags.
pivot: {x: number, y: number} | null
    Authored position in source pixels, measured from the image's top-left.
    null means image center, computed as (width/2, height/2). An explicit
    position can lie outside the image. Coordinates are not normalized.
collider: {enabled: boolean, x: number, y: number, width: number, height: number}
    Axis-aligned rectangle in source pixels. x/y identify its top-left;
    width/height are its dimensions. The rectangle lies within the source
    image. Disabled colliders are represented by enabled:false and four zeros.

Except for unused softkey, the fields listed for each implemented resource
are present in its record. Use null explicitly for nullable fields rather
than omitting them. Additional fields and unknown resource types can be
present and are preserved by Resource Studio.

Map fields

type: "map"
placements: MapPlacement[]
    Ordered sprite instances, TOPMOST FIRST. The first item draws over later
    items. There is no separate z value. Repeated references to the same sprite
    are independent instances.
sideMarkers: SideMarker[]
    Six stored map entries, one for each face. They are not sprite resources
    and are separate from the sprite stacking list.
net: NetSettings
    Geometry and background settings described below.

MapPlacement fields

id: string
    Stable instance identity, unique within this map. Independent of spriteId.
spriteId: string
    Reference to the id of an existing sprite resource, not its name or path.
twistable: boolean = false
    Whether this placed sprite moves with cube twists. Applies independently
    to each placement, not the referenced sprite. Omission means false.
side: integer
    0 TOP, 1 FRONT, 2 RIGHT, 3 BACK, 4 LEFT, 5 BOTTOM.
x: number
y: number
    Sprite pivot position in face-relative ENGINE PIXELS. The face center is
    (0, 0); X increases rightward and Y increases upward. Coordinates can be
    negative or outside the face. These are neither normalized coordinates nor
    top-left image coordinates. Sprite pivot offsets remain source pixels with
    Y downward, as defined in Sprite fields.

SideMarker fields

name: string
    Exactly ~side0 through ~side5, corresponding to side below.
side: integer
    Face ID using the numbering above.
x: 0
y: 0
    The face center in engine coordinates. The marker's canvas position is
    derived from net geometry, not stored here. Hiding markers does not remove
    these six entries.

NetSettings fields and defaults

screenSize: integer = 120
    One display square's size in logical canvas pixels. Each face has 2 by 2
    displays. Canvas pixels per engine pixel k = screenSize / 240.
innerGap: integer = 18
    Gap between displays inside a face, in logical canvas pixels; even.
faceEdgeGap: integer = 18
    Gap between face blocks, in logical canvas pixels.
frame: integer = 1
    Outer frame width, in logical canvas pixels.
padding: {right: integer, bottom: integer} = {right:0, bottom:0}
    Extra canvas area beyond the grid.
lineColor: string = "#252525"
background: string | null = "#8b8b8b"
    RGB/RGBA hex colors; null background means transparent.
markers: boolean = true
    Whether the six side-marker dots are visible in the editor.
markerColor: string = "#ffffff"
    RGB/RGBA hex color for the marker dots.
backgroundImage: string | null = null
    Optional project-relative image path. The image replaces the generated net
    backdrop visually; the computed geometry and stored markers remain intact.
    This is editor presentation, not a reference to a sprite resource.

Geometry settings are independent. Zoom and viewport height are editor view
state and are not stored in the resource JSON. For net geometry details see
media/mapgeometry.js and media/mapgeometry.d.ts.

Placement drawing uses scale = k for FULLSIZE sprites and 2*k for normal
sprites. With face center (cx, cy), a placement's image top-left is:
    left = cx + x*k - pivot.x*scale
    top  = cy - y*k - pivot.y*scale
For a null sprite pivot, use (sourceWidth/2, sourceHeight/2).

Example map resource (sprite_hero references the sprite in the bundle example)

{
  "id": "map_level",
  "name": "level_01",
  "type": "map",
  "placements": [
    {"id": "hero_front", "spriteId": "sprite_hero", "side": 1, "x": 138, "y": 138, "twistable": false},
    {"id": "hero_right", "spriteId": "sprite_hero", "side": 2, "x": -138, "y": -138, "twistable": false}
  ],
  "sideMarkers": [
    {"name": "~side0", "side": 0, "x": 0, "y": 0},
    {"name": "~side1", "side": 1, "x": 0, "y": 0},
    {"name": "~side2", "side": 2, "x": 0, "y": 0},
    {"name": "~side3", "side": 3, "x": 0, "y": 0},
    {"name": "~side4", "side": 4, "x": 0, "y": 0},
    {"name": "~side5", "side": 5, "x": 0, "y": 0}
  ],
  "net": {
    "screenSize": 120,
    "innerGap": 18,
    "faceEdgeGap": 18,
    "frame": 1,
    "padding": {"right": 0, "bottom": 0},
    "lineColor": "#252525",
    "background": "#8b8b8b",
    "markers": true,
    "markerColor": "#ffffff",
    "backgroundImage": null
  }
}

The current resource-builder exports sprites and palettes only. This map
record defines the editor/consumer contract; map binary export needs a compiler
that supports it.

RGB565 mode fields

This is a fragment showing the mode-specific fields; all other sprite fields
remain present as described above.

{
  "paletteId": null,
  "colorMode": "rgb565",
  "blend": "opaque",
  "dither": false,
  "compression": "plain",
  "softkey": null
}

For RGB565 with Color Key, replace the last two fields with:

{
  "compression": "softkey",
  "softkey": {"key": "#ff00ff", "threshold": 0}
}

Font fields

type: "font"
source: string
    Project-relative binary BMFont v3 .fnt file. The file is the authority for
    glyph rectangles, offsets, advances, line height and baseline. These values
    are not duplicated in the JSON.
atlas: string
    Project-relative PNG atlas. Initially resolved relative to source from its
    embedded page filename; may explicitly override that reference. One page.
slot: 1 | 2 | 3
    Unique engine font slot. Slot zero is not a usable font.
paletteId: string
    ID of a palette resource shared by every glyph. May be shared with other
    alpha fonts and sprites, but not opaque sprites.
fullsize: boolean
    Uniform glyph scale: true means source pixels draw 1:1; false means 2x.
    Newly imported fonts default to true.
blend: "alpha"
    All glyphs use alpha blending.

The font record is an editor-level definition, not a dedicated engine resource.
Its supported characters are codes 32–127; character 110 (n) is required.
Glyph identities are font_<slot>_<five-digit-decimal-character-code>, for example
font_1_00065. These identifiers are reserved. They are derived from the slot and
character, not from the font resource's user-facing name. Glyph sprite records
are not stored alongside the font record. PNG and .fnt files remain external
source assets. Preview text, tint and other view settings are not JSON fields.

Example font record (the referenced palette must also exist):
{
  "id": "f1",
  "name": "ui_font",
  "type": "font",
  "source": "assets/fonts/font_1.fnt",
  "atlas": "assets/fonts/font_3_0.png",
  "slot": 1,
  "paletteId": "p1",
  "fullsize": true,
  "blend": "alpha"
}

Sound fields

type: "sound"
source: string
    Source audio file, relative to the folder containing the JSON file. Uses
    forward slashes, without leading slash, parent-directory segments, backslash
    or colon. May be outside sourceFolders while remaining inside the project.

A newly created sound record has exactly the common id/name/type fields and
source. Identity stays unchanged on rename or source replacement. Future fields
are preserved. Duration, sample rate, channel count, source size, waveform,
converted samples and duplicate-source confirmations are not stored in the JSON.
There are no volume, gain, trim, loop, group or tag properties.

Names become SND_<name> at export. They use 1–23 lowercase letters, digits or
underscores and cannot collide with any resource or animation identifier
(including <animation>_end). Reserved names include zero, 0, pal, icon, none,
last, bmp_none, bmp_last, bmp_0, map_none, map_last; Windows device names con,
prn, aux, nul, com0–com9, lpt0–lpt9; and font_<digits>_<five-digit-code>.

Example sound record:
{
  "id": "4f1c2a9e0b7d4c3fa1e5b6c7d8e9f001",
  "name": "coin_pickup",
  "type": "sound",
  "source": "assets/sounds/Coin Pickup.wav"
}
